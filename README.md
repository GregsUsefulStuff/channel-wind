# Channel Islands wind prediction — always-on backend

## What this is

An automated system that:
- Fits a custom per-buoy, per-lead-time weighted blend of six weather models
  (GFS, ECMWF, ICON, UKMO, GEM, HRRR), using whichever combination (fitted
  blend vs. plain averaging) was already proven best through validation.
- Applies that to the live forecast every day, for four Santa Barbara
  Channel / Channel Islands buoys.
- Publishes the result as a small website, with no one needing to run
  anything by hand.

## One-time setup (after uploading these files to your repo)

1. Go to the **Actions** tab of your repository. If GitHub asks you to
   enable Actions, click to enable them.
2. Click **"Monthly weight refit"** in the left sidebar, then **"Run
   workflow"** (manual trigger) to run it once right now. This takes a
   while (it's pulling ~2 years of history for 6 models x 4 buoys) --
   expect it to take a good number of minutes. This creates
   `data/model_weights.json` for the first time.
3. Once that finishes, click **"Daily wind prediction"**, then **"Run
   workflow"** to run it once manually too. This is fast and creates
   fresh content in `data/latest.json`.
4. Visit `https://yourusername.github.io/your-repo-name/` -- it should
   now show live numbers. It may take a minute after the Action finishes
   for GitHub Pages to pick up the change.

After that, both jobs run automatically on their schedules (daily at
~6am Pacific, monthly on the 1st) -- you shouldn't need to touch anything.

## File layout

```
index.html                     the website (reads data/*.json)
data/backtest_summary.json     static historical validation table (context only)
data/model_weights.json        generated by fit_weights.py (monthly)
data/latest.json               generated by daily_predict.py (daily)
data/predictions_log.jsonl     a growing log of past predictions (see below)
scripts/common.py              shared config + fetch/math helpers
scripts/fit_weights.py         the monthly job
scripts/daily_predict.py       the daily job
.github/workflows/daily.yml    schedules the daily job
.github/workflows/monthly.yml  schedules the monthly job
```

## If something fails

GitHub emails you automatically if a scheduled run fails. The most likely
cause is a timeout talking to Open-Meteo or NDBC (these are free public
APIs and occasionally slow) -- usually fine to just re-run manually from
the Actions tab. If it keeps failing, click into the failed run to see
the actual error message.

## Changing which buoys/leads use a fitted blend vs. plain averaging

Edit `BUOYS` in `scripts/common.py`. This is a deliberate, validated
choice per buoy/lead -- don't let an automated process decide this on its
own (see the conversation this came from for why: a system that
constantly re-decides its own method on a small trailing window is prone
to exactly the instability problems that were found and fixed during
development here).

## `data/predictions_log.jsonl` -- not used yet, but collecting data for later

Every daily run appends one line per buoy/lead to this file: what was
predicted, and for which date. Nothing reads this yet. The natural next
step is a script that, once a logged `target_date` has passed, fetches
the actual buoy reading for that date/hour and compares it to what was
predicted -- giving you real, ongoing accuracy tracking instead of trusting
the original backtest forever. Worth building once a few weeks of log
data has accumulated.

## Known limitations (carried over from development)

- Direction's uncertainty cone (`DIR_MAE_DEG` in `common.py`) is a fixed
  number from the original validation, not something refit monthly. Speed
  weights and direction weights ARE refit monthly; the cone width is a
  separate, coarser stat that's fine to leave fixed for now.
- The lookback window is pinned at 2 years. Going much beyond that risks
  evaluating model versions that have since been replaced; going much
  under 1.5 years risks not covering enough seasons to trust the result.
